# ADM

Единый маршрут ребёнка с особенностями развития между медициной,
образованием и соцзащитой Республики Казахстан. Родитель проходит короткое
интервью, сервис собирает персональный план шагов со сроками, куратор
проверяет план и следит, чтобы сроки не сорвались.

Требования — `docs/SPEC.md`, сценарий показа — `docs/DEMO_SCENARIO.md`.

## Структура проекта

**`apps/web` — frontend (Next.js 16, next-intl, PWA на Serwist).**
Пользовательский интерфейс на русском и казахском: пошаговое интервью по
разделам, личный кабинет родителя (план, шаг с подсказкой, календарь,
напоминания, документы) и кабинет куратора (семьи, проверка и подтверждение
плана, просрочки, демо-панель). Устанавливается на телефон как приложение и
открывает последний план без сети.

**`apps/api` — backend (FastAPI, SQLAlchemy, Alembic).**
Серверная логика и REST API под `/api`: авторизация и роли, интервью,
движок правил, кейс-планы с версиями и статусами, эскалация просрочек,
кошелёк документов, уведомления, PDF-отчёты (WeasyPrint).

- `app/modules/interview` — порядок вопросов, валидация ответов, профиль семьи.
- `app/modules/engine` — движок правил R01–R15: из профиля строит шаги плана,
  зависимости и сроки. Детерминированный: одинаковые ответы дают одинаковый план.
- `app/modules/plans` — версии плана, статусы (`draft` → `approved`), правки куратора.
- `app/modules/scheduler` — пересчёт сроков и эскалация (уровни 0–3, текст обращения).
- `app/modules/documents` — загрузка PDF, извлечение текста, срок действия документа.
- `app/modules/notifications`, `app/modules/reports` — уведомления и три PDF-отчёта.

**`data` + `apps/api/alembic` — database (SQLite локально, Supabase Postgres на проде).**
Схема БД — миграции Alembic (`apps/api/alembic/versions`). Справочники —
JSON с JSON Schema в `data/schemas`:

- `services.json` — 15 госуслуг РК по трём ведомствам: ПМПК и её пересмотр,
  заключение ВКК об обучении на дому, направление на МСЭ, освидетельствование
  МСЭ и ИПР, переосвидетельствование, ранняя помощь, КППК, педагог-ассистент,
  выплаты, реабилитация.
- `questions.json` — банк из 18 вопросов интервью с условиями показа.
- `document_types.json`, `providers.json`, `sources.json` — документы,
  организации и нормативные источники.
- `fixtures/case_a.json`, `fixtures/case_b.json` — типовые сценарии
  (первичный маршрут с ПМПК; продление ПМПК с инвалидностью и ИПР). Это и
  демо-данные, и эталон для автотестов.

**`apps/api/app/modules/llm` — ai_agent (OpenAI Structured Outputs).**
Все вызовы LLM идут через `json_schema` со `strict: true`, `temperature: 0`:

- выбор следующего вопроса интервью из допустимых;
- разбор свободного ответа «что беспокоит» (Q17) в флаги профиля;
- объяснение каждого шага плана простым языком на ru/kk;
- распознавание типа и срока действия загруженного документа.

Перед вызовом персональные данные маскируются (имена, ИИН, телефоны, адреса),
ответы проходят фильтр формулировок (без диагнозов) и кешируются. Без
`OPENAI_API_KEY` модуль работает в режиме заглушки на шаблонах.

**Прочее:** `deploy/` и `render.yaml` — запуск всего в одном контейнере на
Render, `vercel.json` — фронтенд на Vercel, `docs/` — спецификация, решения,
открытые вопросы, инструкция по деплою.

## Что готово

**Интервью**
- 8–12 вопросов вместо 18: следующий вопрос зависит от ответов, шесть обязательных.
- Шесть смысловых разделов, вводный экран, страницы перехода между разделами, «Назад».
- Подсказка «зачем спрашиваем» к каждому вопросу, ответ «Не знаю» для дат.
- Восстановление, если анкету открыли в другой вкладке или база сбросилась.

**План и кабинет родителя**
- План строится правилами и проверяется куратором до показа родителю.
- «На этой неделе», маршрут по трём ведомствам, сроки, просрочки с метками «было → стало».
- Экран шага: что сделать, что сначала, что взять с собой (с отметкой «есть»),
  куда обратиться (адрес, телефон, часы), «Я сделал», памятка к визиту в PDF.
- Календарь сроков по месяцам и выгрузка в календарь телефона с напоминаниями.
- Напоминания: «Просрочено», «Скоро срок», лента уведомлений.
- Документы: что не хватает, загрузка PDF или фото с распознаванием срока действия.
- Нижняя навигация со стрелками для телефона, профиль в шапке, светлая и тёмная тема, ru/kk.

**Кабинет куратора**
- Список семей, проверка черновика: правило-источник у шага, убрать или добавить шаг, подтвердить.
- Просрочки по уровням эскалации и готовый текст обращения в ведомство.
- PDF: маршрут и выписка по семье.
- Демо-панель: сдвиг даты на 1/7/30 дней и сброс.

**Сроки и эскалация**
- Пересчёт сроков зависимых шагов при просрочке, уровни 0–3, уведомления родителю и куратору.

**Доступ**
- Вход по email, регистрация родителя без приглашения или по приглашению куратора.
- Демо-вход одной кнопкой: родитель А (интервью с нуля), родитель Б (готовый план), куратор.
- FAQ.

**Качество**
- 179 автотестов (pytest): данные, правила, эталонные планы кейсов А и Б,
  сдвиг времени, интервью, права доступа, отчёты.

## Что не готово или требует проверки

- Реальные вызовы OpenAI написаны, но не проверялись с ключом: без ключа
  работает заглушка.
- Нет OCR сканов (`tesseract`): распознаётся только текст цифровых PDF. Тип
  документа без ключа OpenAI выбирается вручную.
- Работа на Supabase Postgres не проверялась. Демо на бесплатном Render
  использует SQLite и сбрасывает данные при каждом перезапуске.
- Казахские тексты переведены не носителем языка (`needs_review`).
- Сроки 13 из 15 услуг не сверены с нормативкой (`sla_verified: false`).
- Вкладки куратора «Граф», «История» и «Интервью» из SPEC 15.2 сведены в одну страницу.
- Подробности — `docs/OPEN_QUESTIONS.md`.

## Запуск локально

```bash
# API
cd apps/api
pip install -r requirements.txt
cp ../../.env.example ../../.env   # DEMO_MODE=true, DEMO_PASSWORD=...
python -m alembic upgrade head && python -m app.seed
uvicorn app.main:app --port 8000

# Web (второй терминал)
cd apps/web
npm ci && npm run dev              # http://localhost:3000, /api проксируется на :8000

# Тесты
cd apps/api && pip install -r requirements-dev.txt && python -m pytest
```

Демо-аккаунты: `curator@demo.kz`, `parent.a@demo.kz`, `parent.b@demo.kz`,
пароль из `DEMO_PASSWORD`. При `DEMO_MODE=true` на странице входа есть кнопки
входа без пароля.
